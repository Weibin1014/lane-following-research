# CNN and OpenCV comparison experiment results (September 9, 2026)

## Results of this round

In five groups of completed pairing trials, the CNN fixed-throttle scheme hit the line an average of 3 times/lap, while OpenCV hit the line 0 times/lap. The operator confirmed that the five CNN program timings were the running time of each single lap, with an average of 16.132 seconds. OpenCV can accurately restore the forward request span in the log, but does not save the manual stop time, and cannot restore the lap time with the same start and end caliber as CNN from the existing CSV.

## Timing verification and definition

### CNN single lap running time

Using command_duration_s in summary.json, the starting point is after sending local_angle and fixed throttle requests, and the end point is manual interrupt processing. The operator explicitly confirms that this corresponds to a complete lap and is therefore reported as "single lap run time (program timing, manual end)". The five times are 18.142, 16.618, 15.453, 14.831, and 15.617 seconds. All values ​​are retained and the subset close to 15 seconds is not selected. It is not an automatic line crossing timing, and may include communication, startup and manual reaction errors; three decimal places are recording accuracy and are not equal to physical measurement accuracy.

### Advance request span within OpenCV log

Check the original runner in the backup: after output.update in line 129, elapsed_s is collected in line 130, and CSV lines are appended in line 136; the interrupt is captured in line 142, and output.stop is called in line 147, but the interruption time or stop time is not saved. The requested_throttle of the five last frames is 400 instead of 370. Therefore, the stop request occurs after the last CSV time, and the difference is unknown. It cannot mechanically add a frame or replace it with the file modification time.

Definition: T_log = elapsed_s of the last record forward 400 − elapsed_s of the first record forward 400. Five times, the first request to advance is in frame 5. It is the recorded forward interval, not the complete "start request to manual end" interval. It can be used to describe the log duration of this single lap test, but does not fill in the lap_time_s field with the same caliber as CNN.

## Conditions and data sources

- CNN controls steering and local_angle mode for mypilot.tflite, fixed normalized throttle 0.375, current mapping 400; it is not the model that controls the throttle at the same time. OpenCV request 400, the same PWM does not guarantee the same actual speed.
- The same starting point and direction are on-site execution requirements; the battery status is mostly unknown, and the lighting and actual speed are not quantified. CNN does not have an automatic upper limit of 16 seconds consistent with OpenCV.
- Laps, lines, out-of-bounds and intervention are on-site observations without external recording; they cannot be regarded as image recognition accuracy or centimeter-level lateral deviation.
- Raspberry Pi's current DATA_PATH=/home/student/projects/mycar/data, and the number of today's files filtered by modification date is 0; currently RECORD_DURING_AI=False, AUTO_RECORD_ON_THROTTLE=True, AUTO_CREATE_NEW_TUB=False. The backup comparison_results only has a summary, and no frame-by-frame images or inference CSV of this round of CNN were found. The previously provided control script did not explicitly enable recording, and this collection gap will be retained for explanation.
- OpenCV retains each frame's CSV, interval images, and code snapshots; KeyboardInterrupt is interpreted according to the end of the scene, and the original error field is not rewritten.

## Result expressions that can be used in papers

In this round of five completed pairing tests with a fixed throttle request of 400, the number of line collisions per circle of the CNN steering scheme was 3, 2, 4, 3, 3, with an average of 3 times; OpenCV did not observe line collisions five times. Both groups completed trials without out-of-bounds or manual intervention. CNN's program timing and manual end lap time averaged 16.132 seconds. The average forward request span in the OpenCV log is about 14.919 seconds, but due to the lack of the end time and different timing boundaries, we cannot draw conclusions about the speed difference between the two methods based on this. Another CNN non-debugging attempt was not completed due to I/O connection issues reported by the operator and is listed separately. The results support that OpenCV has fewer line collisions under this round of conditions and cannot be generalized to long-term reliability conclusions.
